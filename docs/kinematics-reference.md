# Kinematics reference

Implementation reference for the `kinematics` block: how an evaluator is
expected to consume the graph, and a fully worked example.

The **decision** to pin this contract before building the evaluator, along
with the shape of the graph itself (dofs, bodies, flexures, regions), is
recorded in
[ADR 0003](adr/0003-kinematics-contract-before-evaluator.md). Read that
first. This page is the detail an implementer needs on top of it.

`compile_kinematics` now evaluates body and flexure motion. Its public
docstrings describe array shapes, units, and ownership.
[ADR 0004](adr/0004-flexure-motion-interpolation.md) defines interpolation
and its limits. Shader emission still rejects flexures. Motion bounds support an explicit
flexure opt-in; see the public `infer_motion_bounds` docstring and the
[rendering and bounds proposal](adr/0004-flexure-motion-interpolation.md#rendering-and-conservative-bounds).

## Evaluation semantics

1. **Ownership.** A point belongs to the body or flexure whose `region` SDF is
   smallest (nearest-region). This matches how analytic flexure code already
   classifies vertices (argmin over region SDFs) and is robust near the axis
   where regions are angularly fat.
2. **Body transform.** Compose the body's `motion` ops (each an `expr` of the
   DOFs) into a rigid transform `T_body(dofs)`.
3. **Flexure transform.** `interp(T_from, T_to, blend(p))`, interpolated in
   joint-coordinate space. For revolute bodies sharing an axis this is linear
   interpolation of the authored rotation angle, preserving full turns.
   Other endpoint frames follow a constant relative rigid screw. The blend
   is evaluated at the rest point and clamped to [0, 1].
4. **Vanishing.** With all DOFs at 0 every motion is identity, so the animated
   geometry equals the rest geometry exactly. No at-rest distortion.

The whole evaluation is point-wise and pure → JAX-friendly and runnable at
animation frame rate via per-vertex transforms (no re-mesh).

## Worked example: a notch-hinge flexure

Two rigid blocks joined by a compliant neck, with one revolute DOF. The block on
the left is ground. The block on the right rotates rigidly about the hinge axis
(Z, through the origin) by the `flex` DOF. The neck between them bends, so a
point at along-neck fraction `f` rotates by `f·flex`. This is the whole
vocabulary in its smallest form: a ground body, a DOF-driven body, and one
flexure blending them.

```jsonc
"kinematics": {
  "dofs": [
    { "name": "flex", "kind": "angle", "range": [-10, 10], "default": 0, "unit": "deg" }
  ],

  "bodies": [
    // Empty ops => ground.
    { "name": "block_fixed",  "region": { "$node": "block_fixed" },
      "motion": { "ops": [] } },

    { "name": "block_moving", "region": { "$node": "block_moving" },
      "motion": { "ops": [
        { "kind": "rotate", "axis": [0,0,1], "origin": [0,0,0],
          "angle": { "type": "dof", "name": "flex" } }
      ] } }
  ],

  "flexures": [
    // blend = clamped ramp across the neck: 0 at the fixed face, 1 at the moving face.
    { "name": "hinge_neck", "region": { "$node": "hinge_neck" },
      "from_body": "block_fixed", "to_body": "block_moving",
      "blend": { "type": "field", "kind": "axis_ramp",
                 "params": { "axis": [1,0,0], "lo": -4.0, "hi": 4.0 } } }
  ]
}
```

With `flex = 0` this is identity (rest geometry). Sweep `flex` and the right
block swings while the neck bends. A host reads this and animates with one
slider. Nothing part-specific lives in the host.

The same pattern extends to a serial chain by repetition: `n` bodies where body
`k` moves by `k·dof`, joined by `n-1` flexures, each blending its two
neighbours. Nothing in the schema changes, only the number of entries.

`region` refers to named nodes via `{"$node": ...}`, reusing the trees the part
already builds, so the graph adds almost no new authoring. Regions are views,
not instances: naming a node does not duplicate it.

The runnable version of this example is
`examples/notch_hinge_kinematics.sdm`, regenerated by
`examples/build_notch_hinge_kinematics.py`.
